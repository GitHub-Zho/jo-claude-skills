# 内容与取舍

## 1. 事实母表

为每个事实记录来源、状态和可公开程度。若多个版本冲突，正文不自行选值；优先使用用户最新确认或正式材料。可以中性化项目性质，但不能升级为学位、正式交换、论文发表或业务成果。

状态定义：

- 已验证：来源明确且版本一致。
- 有冲突：来源间数值、日期或性质不一致。
- 待核验：只有单一旧材料或存在合理疑问。
- 不采用：低相关、重复、不可验证或会稀释主线。

## 2. 岗位证据映射

从目标岗位提取 6–12 个能力主题，例如 Agent 编排、RAG、VLM、生成模型、召回排序、训练/推理、并发与系统基础。为每个主题填写：

| 能力主题 | 事实证据 | 放置位置 | 关键词 | 状态 |
|---|---|---|---|---|
| Agent 编排 | 项目中的规划、路由、QA gate | 项目经历 | orchestration, routing | 已验证 |

关键词必须出现在能解释它的事实附近，不建立脱离证据的关键词墙。

## 3. 技术叙事单元

每个实习或项目至少回答其中三项，复杂项目应回答四至五项：

1. 面向什么任务、问题或约束？
2. 本人负责哪一部分？
3. 使用什么模型、算法、系统或数据流程？
4. 为什么采用这一机制，解决了什么难点？
5. 如何验证结果，或交付了什么可检查的工程产物？

推荐句法：

> 设计/实现【对象】，采用【方法与关键机制】解决【约束或难点】，并通过【指标、测试或工程产物】验证【结果】。

没有量化指标时，以真实的功能覆盖、流程闭环、测试、部署范围或系统行为收束；不得补造数字。

## 4. 长度与密度

- 不设“每条必须一行或两行”的上限。
- 一段包含一个主要结论；复杂链路可拆成 2–4 个说明段落。
- 先写不受页数限制的完整内容版，再删除重复和低价值信息。
- 两页优先；必要内容在舒适字号下无法容纳时，允许三页。
- 压缩顺序：重复措辞 → 低相关内容 → 句法冗余 → 模块间距 → 页边距 → 极小幅字号调整。
- 不得用删模型机制、系统边界、个人贡献或验证方式来换取页面整齐。

## 5. 适合中文应届技术简历的顺序

联系方式 → 求职方向 → 教育背景 → 专业技能 → 实习/科研 → 代表项目 → 奖项。

有强实习时先实习；项目按岗位相关度排序，而非机械按日期排序。系统基础项目可作为能力补强，但不要恢复无方法、无结果、与目标岗位无关的课程作业。

## 6. Resume Builder 可借鉴的部分

借鉴结构化事实档案、岗位证据映射、真实指标、单栏 ATS 结构、按完整信息块分页和交付前人类化检查。不要照搬北美 Letter 纸、英文 Summary/References、固定两页或强制一行 bullet。
