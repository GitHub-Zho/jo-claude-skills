# 交付检查

## 内容

- [ ] 姓名、电话、邮箱、链接、日期和机构名称与来源一致。
- [ ] 项目性质、个人贡献、技术栈、指标和奖项没有夸大。
- [ ] 所有冲突已由用户确认或采用中性表述并明确待核验。
- [ ] 每个核心项目保留任务、方法/机制、贡献边界和结果/产出。
- [ ] 低相关项目的删除基于相关性，而不是行数限制。

## 视觉

- [ ] 页面为 A4，版心边界和参考稿一致或有明确理由。
- [ ] 上下安全区由真实页面边距提供；没有用连续普通空行或页尾空段落撑版面。
- [ ] 若使用转换器兼容留白，它只存在于导出副本中，且高度来自 PDF 实测补差。
- [ ] 中文字体在本机存在，并有真实 Regular/Bold 字重。
- [ ] 姓名、模块、项目、正文和辅助信息层级肉眼可辨。
- [ ] 中西文没有自动插入的异常空格；标点、大小写和日期格式统一。
- [ ] 日期固定在正文右边界内，没有超出版心或挤压长标题。
- [ ] 没有标题孤行、项目块无意义跨页、单字尾行、裁切或重叠。
- [ ] 不因追求 1–2 行或固定两页而删除关键技术内容。

## 文件与 ATS

- [ ] DOCX 可正常打开并保留可编辑样式。
- [ ] PDF 页数、A4 尺寸、字体替换和嵌入状态已检查。
- [ ] PDF 可复制/提取文本，阅读顺序正确，无乱码和空白页。
- [ ] 姓名、联系方式、学校、公司、日期和关键词均位于正文文本层。
- [ ] 黑白预览中标题、正文、链接和加粗仍能区分。

## 渲染回归

1. 把 DOCX 渲染为 PDF。
2. 把每页 PDF 渲染为图片，按 100% 视觉检查。
3. 与参考稿并排比较：版心、首尾位置、字号、字重、颜色、段距、右侧日期和分页。
4. 修正后重新渲染，直到没有明显替换字体、漂移、异常空格或信息块断裂。
5. 最终交付 DOCX；若用户需要，再交付已验证 PDF。
